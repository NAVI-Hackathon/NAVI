# NAVI · 三分鐘展示

> 定稿：2026-10-24（Sh 確認）；2026-10-26 更新：線上一般模式已是 Live，展示與錄影改用示範模式。錄影與現場展示以線上版本為準；畫面凍結版本為 main `ed01d19`，之後前端只修 bug、不改外觀。

「法國巴黎人壽智慧服務導航：像聊天一樣說出你的情況，NAVI 先問清楚、從官網資料找答案，再一步一步帶你到正確的頁面與服務入口。」

## 流程（3 分鐘）

| 時間 | 操作 | 畫面結果 | 講稿重點 |
| --- | --- | --- | --- |
| 0:00–0:20 | 在模擬官網「理賠程序介紹」（主要網址）切換幾個分頁 | 官網資訊分散在多頁、多個分頁與表格 | 痛點：保戶得自己找功能、讀完說明才知道要準備什麼 |
| 0:20–0:30 | 點右下角 **NAVI** | 聊天室在官網內開啟；NAVI 打招呼並給 4 個選項 | 不用離開官網，像聊天一樣，不知道怎麼問就點按鈕 |
| **一、先問清楚（多輪對話）** | | | |
| 0:30–0:50 | 在底部輸入框打「理賠要準備什麼文件」→ Enter；NAVI 反問後點「**醫療門診**」 | NAVI 反問「你要申請哪一種？」；選擇後只列 3 個重點，可按「看完整說明」 | 問題太籠統時先問清楚，不亂給答案；回答精簡，不用讀一大段 |
| 0:50–0:55 | 點答案下方「依據：官網・…」 | 展開資料快照原文摘錄、擷取日期與「N 天前」、官網原頁連結 | 每個答案都附官網原文與日期，不是 AI 自己寫的 |
| **二、帶你去（第二場景：地址變更）** | | | |
| 0:55–1:25 | 打「我搬家了，保單上的地址要怎麼改？」→ 點「**帶我去：查看變更戶籍地址／收費地址**」→「下一步」→「下一步」→「完成導覽」 | 3 步導覽卡：變更說明 → 下載契約變更申請書 → 服務入口；官網跟著換頁、框出位置 | **不只回答，還一步一步帶到功能入口**（題目要求「找到功能入口」）。只做頁面導覽，不代登入、不填表、不送件 |
| **三、護欄** | | | |
| 1:25–1:35 | 打「推薦我買哪張保單」 | 「這個問題需要由專人協助」＋客服專線，附其他選項 | 不給投保建議、不判斷能否理賠，不會編造答案 |
| **四、住院理賠完整旅程** | | | |
| 1:35–1:50 | 打「我上週在台中榮總住院五天，要怎麼申請理賠？」→ 點旅程卡片的「**開啟工作區**」 | 對話中出現旅程卡片（35%、下一步）；工作區辨識臺中榮民總醫院為醫起通合作醫院 | 一句話建立服務旅程：要準備什麼、走哪個管道 |
| 1:50–2:05 | 點「使用範例文件」（診斷書） | **70%**；理賠文件健檢列出已取得各項「+20%、+15%」；標示「示範辨識資料，非真實文件分析。」 | 70% 怎麼來的一目了然：已取得／需要補件／需要人工確認 |
| 2:05–2:12 | 點「帶我去：查看匯款給付規定」 | 官網框出「匯款給付需提供存摺影本」（窄螢幕時 NAVI 收合，按右下「**回到 NAVI・繼續下一步**」回來） | 每一步都能回到官網原文 |
| 2:12–2:22 | 上傳範例存摺 | **90%**，帳號只顯示末四碼 | 個資最小化：瀏覽器只存案件編號 |
| 2:22–2:40 | 確認資料（勾選兩項）→ 前往服務入口 | **100%**；建議醫起通並列出注意事項 | 100% 只代表資料準備完成，不代表理賠核准或已送件 |
| 2:40–2:52 | （時間夠才做）「需要協助？轉由專員接續」→ 勾選確認 →「確認並取得摘要」 | 「已取得摘要・尚未送出」；摘要不含描述、姓名、醫院、日期、帳號 | 使用者確認後才取得交接摘要；示範不會真的送出 |
| 2:52–3:00 | 結語 | | 「**理解、檢核、帶你去**」：先問清楚、看懂缺什麼、帶到正確入口 |

**兩分鐘版**：省略護欄（1:25）、存摺（2:12）與交接（2:40）。多輪對話（0:30）保留，這是與一般問答最明顯的差異。

## 一定要講清楚的事

- 100% 只代表原型定義的資料準備完成，**不代表保障適用、理賠通過、已申請或已核付**。
- 答案與導覽都來自團隊整理的官網公開資料。每則資料標示各自的擷取日期；沒有逐條日期的標「資料集整理日期」。摘錄是本地資料快照，**不是即時查核官網**。
- 示範模式的文件辨識是合成資料，畫面已標示；不要說成 AI 實際讀了文件。
- 交接只會「取得交接摘要」，**不會轉交專員、建立案件或送出申請**。
- 模擬官網是團隊重建的示範網站，頁尾標註「InsurHack 模擬網站，非官方」。

## 彩排注意

- 住院場景用「帶我去：**查看匯款給付規定**」（單一步驟）。不要用「查看住院醫療應備文件」：那是 3 步導覽，最後一步帶到「郵寄申請」，和本案建議的醫起通不一致，容易被追問。
- NAVI 在問題太籠統時會**追問一次**（選項會連同原本的問題重新查詢）。講稿說「先問清楚」即可，不要說成能連續深入對談。
- 住院要多按一次「**開啟工作區**」；在工作區按 NAVI 標誌可回到聊天室，對話保留，旅程卡片的進度會跟著更新。
- 在聊天輸入框按 Enter 送出，Shift+Enter 換行。

## 備用題（評審追問時）

| 輸入 | 結果 |
| --- | --- |
| 保單借款多久撥款 | 審核無誤後約 5–7 個工作天，免手續費；附「保單借款」「保單借款還款」選項 |
| 家人過世不知道有沒有保險 | 「戶政連線‧理賠免奔波」：辦死亡登記時同時申請 |
| 癌症理賠需要哪些文件 | 「防癌或重疾理賠應備文件」（「癌症」對應官網用語「防癌」） |
| 受益人變更表單在哪下載 | 「受益人變更申請書」；帶我去為 2 步導覽（申請書 → 變更受益人說明） |
| 密碼輸錯被鎖住了 | 常見問題：錯誤 5 次鎖定帳號，需打客服解鎖；帶我去為 2 步導覽 |
| 我在榮總住院五天（沒說哪一家） | 不猜院所：建議聯盟鏈或郵寄，並請提供醫院全名 |
| 住院旅程中，在「AI 助手」問「線上申請還要寄正本嗎？」 | 挑出官網原文：10 日內須寄回正本；超過 30 萬元需等正本寄達 |
| 今天天氣如何 | 「我還需要一些資訊」，並給可辦理的服務選項，不硬湊答案 |

## 出狀況時

| 狀況 | 處理 |
| --- | --- |
| NAVI 面板顯示「NAVI 暫時無法連線」 | 按「改用示範模式」，流程相同 |
| 「分析服務暫時無法使用」或 API 無回應 | 改開主要網址（示範模式），或 https://app.navitw.com/demo |
| 正式 Live 顯示「今日 AI 分析次數已用完」或「這次體驗的 AI 分析次數已用完」 | 正常：免費額度保護，不會改用假資料。改用示範模式（訊息裡附網址） |
| NAVI 顯示「這份服務旅程已失效」 | 正常：後端重啟或超過 1 小時，重新描述即可 |
| 交接時出現「案件資料已更新，請重新查看摘要」 | 正常（確認前案件有變動），按「重新整理摘要」再確認 |
| VPS 整個連不上 | 改用本機 `npm run dev:all` |
| 評審問「有用 AI 嗎」 | 後端已串接 Gemini 3.1 Flash-Lite 做意圖理解與文件辨識（限免費方案、有成本保護）。線上一般模式 https://navitw.com/ 就是 Live，可用合成範例實際辨識；展示用示範模式，確保穩定、不耗額度。尚未開放真實理賠文件。準備度與分數由後端規則決定，AI 只負責理解描述（AI interprets. The system decides.）；知識問答一律只引用官網資料，不讓 AI 生成答案 |
