# NAVI 使用者任務測試：測試計畫與主持人腳本

> 版本 2026-10-27（Developer A）。目的是**實際量測**，不是證明 NAVI 一定比較好：結果照實記錄，NAVI 較慢或失敗也要寫進去。人數不足時，報告標明小樣本，不推論母體。

## 1. 要回答的問題

在**同一個模擬官網**上，第一次使用的人完成三類常見任務時，使用 NAVI 跟只用網站選單比起來：

1. 完成率是否不同？
2. 完成時間是否不同？
3. 點錯的次數、需要協助的次數是否不同？
4. 主觀難易度與對結果的信心是否不同？

## 2. 受試者

- 6～10 位**非開發者**（不是本隊成員、沒看過 NAVI 展示）。最好有使用保險官網的經驗，但不限定。
- 記錄代號（P01、P02…），不記錄姓名、電話、學號或保單資料。
- 開始前口頭說明並取得同意（第 6 節台詞）。可以隨時停止。

## 3. 設計：受試者內比較＋平行任務組

每位受試者完成**兩個條件**，每個條件做一組**不同但難度相近**的任務，避免同一題做第二次變快：

| 條件 | 網址（同一台電腦、同一個瀏覽器、無痕視窗） |
| --- | --- |
| A：不使用 NAVI | `https://navitw.com/?navi=off`（右下角不會出現 NAVI，站內換頁也維持隱藏） |
| B：使用 NAVI | `https://navitw.com/?navi=demo`（示範模式：使用本地官網資料，不消耗 Gemini 額度） |

> 為什麼 B 用示範模式：答案與導覽都來自同一份官網資料快照與規則；示範模式只是不呼叫 Gemini，避免每日額度與網路延遲影響量測。這三類任務都不需要文件辨識。報告中須寫明「B 條件為示範模式」。

| 任務組 | 1. 找服務入口 | 2. 找理賠應備文件 | 3. 找表單並下載 |
| --- | --- | --- | --- |
| X | 地址變更 | 住院醫療 | 保險契約內容變更申請書（投資型） |
| Y | 變更受益人 | 防癌或重疾 | 保險金申請書 |

**順序輪替**（降低學習效應與題組難度差）：依報到順序循環指派。

| 順序 | 第一段 | 第二段 | 受試者 |
| --- | --- | --- | --- |
| 1 | A＋X | B＋Y | P01、P05、P09 |
| 2 | B＋X | A＋Y | P02、P06、P10 |
| 3 | A＋Y | B＋X | P03、P07 |
| 4 | B＋Y | A＋X | P04、P08 |

同一段內，任務依 1 → 2 → 3 的順序進行。

## 4. 任務與成功判定

任務卡用生活化的描述，不直接照抄網頁上的標題（表單題例外：現實中客服會告訴你表單名稱）。卡片內容見 [task-cards.md](task-cards.md)。

| 題 | 成功＝受試者說「找到了」時，畫面上能看到 | 不用 NAVI 的最短路徑（從首頁） |
| --- | --- | --- |
| X1 | 保單變更頁「變更戶籍地址 / 收費地址」那一段 | 保單變更（預設分頁）：1 次點擊 |
| Y1 | 保單變更頁「變更受益人」那一段 | 保單變更 → 受益人變更分頁：2 次 |
| X2 | 理賠程序介紹「應備文件」表格中的「住院醫療」那一列 | 理賠程序介紹 → 應備文件：2 次 |
| Y2 | 同上，「防癌或重疾」那一列 | 理賠程序介紹 → 應備文件：2 次 |
| X3 | 常用表單下載中「保險契約內容變更申請書（投資型）」並按下「下載」 | 常用表單下載 → 下載：2 次 |
| Y3 | 常用表單下載「理賠服務表單」中的「保險金申請書」並按下「下載」 | 常用表單下載 → 理賠服務表單 → 下載：3 次 |

- 使用 NAVI 時，只要 NAVI 帶到正確位置（官網框出目標）且受試者確認，即算成功；在聊天室讀到答案但沒有到官網正確位置，**不算**成功。
- 每題上限 **180 秒**。超過、放棄、或指錯位置且不再嘗試，記為未完成。
- 受試者說「找到了」但位置錯誤：主持人只說「再看看」，不給提示，繼續計時。

## 5. 量測定義（請與 Developer B 的量測定義一致）

| 欄位 | 定義 |
| --- | --- |
| `time_s` | 受試者唸完任務卡、主持人說「開始」起，到受試者在**正確位置**說「找到了」為止的秒數。未完成填 180。 |
| `success` | 1＝180 秒內、未獲協助、到達正確位置；0＝其他。 |
| `wrong_clicks` | 點到最短路徑以外的頁面、分頁或選項的次數（含 NAVI 中選錯的選項；捲動不算點擊）。 |
| `help` | 主持人是否給過任何提示（是＝1）。給提示後該題 `success` 記為 0。 |
| `seq` | 單題難易度（Single Ease Question）：「整體來說，這題有多容易？」1 非常困難～7 非常容易。 |
| `confidence` | 「你有多確定找到的是正確的？」1 完全不確定～7 非常確定。 |
| `notes` | 卡住的地方、說了什麼（不記個資）。 |

## 6. 主持流程與台詞（每人約 15 分鐘）

1. **說明與同意（1 分鐘）**
   「謝謝你來幫忙。我們在測一個保險網站的使用方式，不是在測你；找不到也完全沒關係，那正是我們想知道的。全部只用假資料，請不要輸入你自己的保單、病歷或帳戶資料。我會計時並記錄你點了哪裡，不會記你的名字。隨時可以停止。可以開始嗎？」
2. **條件說明**
   - A：「這一段請只用網站本身的選單和頁面，不要用搜尋引擎。」
   - B：「這一段可以用右下角的 NAVI：它像客服聊天室，你可以用自己的話問。」（只說這一句，不示範。）
3. **每一題**：把任務卡交給受試者 → 受試者唸一次 →「準備好就說開始」→ 計時 → 結束後立刻問 `seq`、`confidence`。
   - 過程中不回答操作問題；被問時說「你覺得應該怎麼做，就怎麼做」。
   - 請受試者不要邊做邊大聲解說（會影響時間），做完再問。
4. **兩段都結束後（3 分鐘）**
   - 「兩種方式，你比較想用哪一種？為什麼？」
   - 「NAVI 有沒有讓你覺得不放心或看不懂的地方？」
   - 「還有什麼想說的？」
5. 每段之間**關閉並重開無痕視窗**，清除聊天紀錄與頁面狀態。

## 7. 環境與準備

- 同一台筆電、Chrome 或 Safari、視窗寬 1280 以上；用滑鼠或觸控板。
- 開始前確認：`https://navitw.com/?navi=off` 沒有 NAVI 按鈕；`https://navitw.com/?navi=demo` 打開 NAVI 頂端顯示「示範」。
- 計時用手機碼錶；紀錄用 [record-sheet.csv](record-sheet.csv)（每人每題一列）。
- 不錄臉、不錄聲音；若要螢幕錄影，先取得同意，分析後刪除。

## 8. 分析與報告

- 執行 `node scripts/usability/summarize.js docs/usability/record-sheet.csv` 產生摘要：每個條件的完成率、完成時間中位數（只計成功者）、錯誤點擊平均、需協助比例、`seq` 與 `confidence` 平均，以及每位受試者兩條件的差異。
- 樣本少於 10 人時**不做顯著性推論**，只報描述統計與個別差異，並寫明人數與順序分布。
- 結果寫入 [results.md](results.md)，同時保留原始 CSV。不刪除不利於 NAVI 的資料；若需排除某筆（例如設備故障），寫明原因。

## 9. 已知限制（需寫進報告）

- 受試者是方便取樣，不代表法巴人壽的保戶族群。
- 模擬官網為團隊重建，與真實官網的版面、搜尋功能不同。
- B 條件使用示範模式；Live 模式的回應時間會更長且可能受額度限制。
- 表單題提供了表單名稱，可能較有利於直接瀏覽選單。
