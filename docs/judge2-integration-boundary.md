# Integration Boundary Report — 第二位評審

沿用核心：Intent/Knowledge、原文 Evidence、確定性 Workflow、Readiness、Navigation Plan、Provider 隔離及本地 Knowledge Lifecycle。本輪只補管道語意、證據歸屬與公開 URL，不建立新引擎。

| 邊界 | 目前完成 | 企業需要提供 |
|---|---|---|
| 官網定位 | 自建模擬官網，可信路由／錨點＋建置 manifest | 官方 Router/DOM adapter、穩定錨點、變更通知、核准 iframe origins/CSP |
| 身分／案件 | 原型合成測試 Session 隔離，重啟／TTL到期 | SSO/身分認證、案件授權、持久化及跨裝置政策 |
| 保單與管道 | 公開快照說明；個人管道條件待確認 | 會員／保單／服務條件 API、授權範圍、來源規則擁有者 |
| 文件 | 實際 bytes → Provider → 欄位／一致性檢查 | 正本/簽章驗證、完整解碼與掃描、核准資料處理合約、加密與保留／刪除流程 |
| 客服 | 遮蔽摘要，使用者確認；不真正傳送 | CRM/客服 API、交接同意、傳送回條、稽核及保管責任 |
| 法遵 | 原型、非官方、只限合成資料告知 | 法務／資安／個資審查、合法依據、供應商條款與資料地域評估 |

未獲授權的保險公司內部系統沒有登入或測試。模擬網站通過不等於官方網站已整合。

## 可追溯成本模型

- 原型新付費依賴／本輪付費 API：0。Free Tier 不代表已購買 VPS、網域、人工審核及整合成本為0。
- 原型程式預設 durable daily cap=12、process cap=12；Production 設定及實測見本輪執行報告。不得用程式預設值冒充線上值，也不把本地預算當成 Google 專案配額。
- 一般住院流程約3次生成：Intent一次＋兩份文件各一次；receipt 命中可避免建立案件重複理解。失敗也佔預算；人工確認、重試和額外任務會增加需求。20次只能在全部成功且沒有其他用途的假設下容納6次三生成流程，並非保證容量。
- 企業成本：`生成量×核准單價 + VPS/運算與儲存 + 內容審核工時×人力成本 + 身分/保單/官網/CRM整合 + 法遵資安與維運`。
- 稽核輸入來源：server config（僅核准非秘密欄位）、持久用量帳本、模型事件、Cloud/VPS/網域帳單、審核與整合工時表。後三項尚無實際金額／工時資料，單價和總成本列 unknown，不填推測報價。
- 真實醫療／銀行資料公開上傳保持禁止；免費服務的資料使用政策須在企業階段重新審核，不能因有HTTPS就解鎖。
